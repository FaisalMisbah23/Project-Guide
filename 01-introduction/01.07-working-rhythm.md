# 01.07 - Your working rhythm

**Where the project is now:** You understand the product, audience, scope, prerequisites, and course path. Now set the habits that keep the build steady.

**This step:** Use commits, notes, environment hygiene, and browser verification as part of the build.

## Work in small loops

For most lessons, use this rhythm:

1. Read the goal and identify the files involved.
2. Make the smallest useful change.
3. Run the relevant command or open the relevant route.
4. Fix confirmed errors.
5. Commit once the chapter checkpoint is real.

Small loops make debugging easier. If something breaks, you know which change likely caused it.

## Keep proof close to the work

When a page changes, open it. When a form changes, submit it. When database behavior changes, run the Prisma command or route that proves it. When a security boundary changes, test both the allowed and blocked paths.

## Keep notes

After each chapter, write a few short notes:

- The decision this chapter forced you to make
- The tradeoff you accepted
- The bug, risk, or confusing idea you would watch for next time

These notes become useful when you later explain the project in interviews or improve it after deployment.

## Continue when

You have a repeatable build rhythm: small changes, visible verification, clean commits, and brief notes.
