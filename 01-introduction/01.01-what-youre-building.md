# 01.01 - What you're building

**Where the project is now:** You are at the start of the course. There is no app yet, only the product target and the working rules that will guide every chapter.

**This step:** Orient yourself around a professional portfolio that is also a small publishing system.

## The product

You are building a software-engineer portfolio that does more than introduce you. The finished site will present your story, show project case studies, publish articles, protect an admin workflow, receive contact messages, and deploy cleanly.

That combination matters. A portfolio is public proof, but a maintained portfolio is also an application. It has routes, content models, validation, security boundaries, environment variables, database migrations, and production checks.

## What the finished app should prove

- You can design readable public pages for real visitors.
- You can model content instead of hardcoding every screen.
- You can separate public routes from private admin routes.
- You can work with a database, migrations, and deployment settings.
- You can verify behavior instead of trusting that code "looks right."

## What this is not

This is not a static resume clone, a collection of decorative sections, or a copy-paste template. The goal is to build something you can explain in an interview and continue maintaining after the course ends.

## Continue when

You can describe the final product in one sentence and name the major parts it contains: public portfolio, project proof, articles, admin workflow, contact, and deployment.
