# 01.02 - How to use this course

**Where the project is now:** You know the product target. Next you need a way to move through the guide without turning it into a pile of disconnected tasks.

**This step:** Work chapter by chapter, finish every checklist, and keep commits small.

## The pattern

Each chapter gives you a product outcome, a set of files or behaviors to add, and a checklist gate. Build the chapter in order, verify the result, commit it, then move on.

Do not skip checklist files. They are there to catch the quiet failures: broken mobile layout, missing environment notes, public drafts, admin routes without protection, or code that works locally but cannot build.

## How to read each lesson

- **Where the project is now** tells you the current state before the lesson starts.
- **This step** tells you the specific goal.
- **Why this matters** explains the product or engineering reason.
- **Build sections** give paths, contracts, and commands.
- **Continue when** defines the minimum proof before moving forward.

## Your job while following it

Keep a terminal open, keep the app running when there is an app to run, and check `git status` often. When a lesson asks for a file, create it in your own project repo. When a lesson asks for behavior, verify it in the browser or terminal before calling it done.

## Continue when

You understand that each chapter ends with a working state, a clean commit, and enough verification notes that you could explain what changed.
