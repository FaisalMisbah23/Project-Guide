# 03.10 - Accessibility pass

**Why this step matters:** Check landmarks, keyboard focus, link names, and color contrast.

**Where the project is now:** You have completed the previous sub-chapters in **Design system and shell**. This step adds one concrete piece and should end with something observable.

## What you must do

Check landmarks, keyboard focus, link names, and color contrast. Use the file or folder named in the step title and place it in the smallest matching area of the project: `app/`, `components/`, `lib/`, `prisma/`, `public/projects/`, or `docs/`.

Name the file deliberately. If this step mentions a route, create it under `app/`. If it mentions reusable UI, create it under `components/`. If it mentions data access, create or extend a file under `lib/`. If it changes the database shape, update `prisma/schema.prisma` and run a migration.

## Required behavior

```text
Input: the page, form, route, or helper receives the data described by this sub-chapter.
Output: it returns a predictable UI state, JSON response, redirect, or database record.
Failure: invalid input, missing records, and unauthorized access produce clear non-success behavior.
```

Keep the implementation small. This sub-chapter should not quietly implement a later chapter.

## Verification

Use the narrowest check that proves this step:

```bash
npm run lint
npm run build
```

Also verify the feature directly. That may mean opening the route in the browser, submitting the form, checking the database with Prisma Studio, or sending a request to an API route.

## Do / Don't

**Do:** keep public behavior and admin behavior separate, even when they read the same article or project data.

**Do:** commit after this step if the app still runs.

**Don't:** paste a full finished solution from another project. Use the contract above and write the logic yourself.

**Don't:** store secrets in `NEXT_PUBLIC_*` variables unless the value is intentionally public.

## Hint

If you are stuck, describe the behavior in one sentence before writing code. For example: "An unauthenticated admin request redirects to `/admin/login`." That sentence usually reveals the route, input, and expected output.

## What's next

Continue to the next numbered sub-chapter only after this behavior is visible or testable.
