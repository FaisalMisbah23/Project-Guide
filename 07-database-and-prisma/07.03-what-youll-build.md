# 07.03 - What you'll build

**Where the project is now:** You are working toward a deployable software-engineer portfolio, not a static resume page. The finished product will show projects, publish articles, protect an admin workflow, accept contact messages, and deploy cleanly.

**This step:** Add env files, Prisma schema, migrations, and a shared client.

## Why this matters

A portfolio is often judged quickly, but it is still a real application. The professional move is to build the visible pages and the operational parts together: content, data, security, and deployment all shape whether the site can be trusted.

The tempting shortcut is to make a few attractive sections and call the project done. That creates a fragile showcase: projects are hard to update, articles cannot be managed, and deployment problems arrive late. This guide instead grows the app in small, reviewable steps.

## In plain English

- **App Router** means routes are folders under `app/`.
- **Server Component** means a React component that can read data on the server before HTML reaches the browser.
- **Client Component** means a component that runs in the browser because it needs state, effects, or events.
- **Repository function** means a small data-access function that keeps Prisma queries out of page components.

## What to keep in mind

Work in your own app repo. The guide gives contracts, paths, checks, and constraints. You write the implementation, then prove it works with browser checks, command output, and clean commits.
